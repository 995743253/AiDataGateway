# AiDataGateway 定制化模块开发指南

本文面向企业内部或个人扩展开发者。定制化模块可以在不把私有规则合并到 AiDataGateway 主仓库的情况下，同时增加一个管理页面和一组 MCP 工具。典型场景包括低代码元数据解析、内部表结构分析、日志诊断、服务器容量报告，以及把专有模型转换成代码、伪代码或图形。

## 1. 安全模型

扩展 DLL 在 AiDataGateway 进程内运行，不是安全沙箱。它与网关拥有相同的 Windows 用户权限，扩展页面也与管理端同源。因此：

- 只安装来源可信、经过代码审核并由企业自行保管的扩展包。
- 不要把客户专有 DLL、规则文件或前端制品提交到公开主仓库。
- 网关不会把数据库密码、Seq API Key 或其他凭据交给扩展。
- 数据库、日志和指标访问应使用 `IGatewayExtensionContext` 提供的服务；数据库查询仍会经过项目关联校验、只读 SQL 校验、表黑名单、最大返回行数、超时和审计。
- 当前公开数据库服务只允许查询，不向扩展公开直连字符串或写操作。需要修改数据库时仍应使用网关已有的审批链路。

程序集加载上下文用于依赖隔离和热更新，不构成权限隔离。模块升级或删除无需重启网关；纯托管程序集从内存加载，不会长期锁定 DLL 文件。

## 2. 扩展包结构

管理员在“定制化模块 → 模块中心”上传一个不超过 100 MB 的 ZIP：

```text
my-private-extension.zip
├── gateway-extension.json
├── Company.PrivateExtension.dll
├── Company.PrivateDependency.dll       # 可选
└── wwwroot/
    ├── index.html
    └── assets/                         # Vue/Vite 打包制品，可选
```

`gateway-extension.json` 必须位于 ZIP 根目录：

```json
{
  "id": "company-metadata",
  "entryAssembly": "Company.PrivateExtension.dll",
  "entryType": "Company.PrivateExtension.MetadataModule",
  "contractVersion": 1,
  "enabled": true
}
```

| 字段 | 说明 |
| --- | --- |
| `id` | 全局唯一模块标识；小写字母开头，只能包含小写字母、数字、`.`、`-` |
| `entryAssembly` | 入口 DLL 在包内的相对路径 |
| `entryType` | 实现 `IGatewayExtension` 的公开完整类型名，必须有无参构造函数 |
| `contractVersion` | 当前固定为 `1` |
| `enabled` | 安装后是否立即加载，默认 `true` |

ZIP 中不应包含 `AiDataGateway.Extensions.Abstractions.dll`，运行时会使用网关自带的契约程序集。压缩包最多 2,000 个文件；入口 DLL、前端入口和所有静态资源必须位于扩展包目录内。

## 3. 创建后端 DLL

扩展项目目标框架为 `.NET 10`，引用公开契约项目或以后发布的同名 NuGet 包：

```xml
<Project Sdk="Microsoft.NET.Sdk">
  <PropertyGroup>
    <TargetFramework>net10.0</TargetFramework>
    <Nullable>enable</Nullable>
    <ImplicitUsings>enable</ImplicitUsings>
  </PropertyGroup>
  <ItemGroup>
    <ProjectReference Include="..\..\src\AiDataGateway.Extensions.Abstractions\AiDataGateway.Extensions.Abstractions.csproj" />
  </ItemGroup>
</Project>
```

最小入口示例：

```csharp
using System.Text.Json;
using AiDataGateway.Extensions;

public sealed class MetadataModule : IGatewayExtension
{
    private static readonly JsonElement Schema = JsonSerializer.SerializeToElement(new
    {
        type = "object",
        properties = new
        {
            projectCode = new { type = "string" },
            dataSourceKey = new { type = "string" }
        },
        required = new[] { "projectCode", "dataSourceKey" },
        additionalProperties = false
    });

    public GatewayExtensionDefinition Definition { get; } = new(
        Id: "company-metadata",
        Name: "企业元数据分析",
        Version: "1.0.0",
        Description: "读取项目数据源并按企业私有规则生成伪代码。",
        PageTitle: "元数据分析",
        FrontendEntry: "wwwroot/index.html",
        Tools:
        [
            new("analyze", "解析指定项目的低代码元数据。", Schema,
                GatewayExtensionCapability.QueryExecute)
        ]);

    public async Task<JsonElement> InvokeAsync(
        string operation, JsonElement arguments,
        IGatewayExtensionContext context, CancellationToken cancellationToken)
    {
        if (operation != "analyze") throw new ArgumentException("Unknown operation.");
        var project = arguments.GetProperty("projectCode").GetString()!;
        var source = arguments.GetProperty("dataSourceKey").GetString()!;
        var rows = await context.Database.QueryAsync(project, source,
            "select PageName, ControlJson from PrivateMetadataPages", cancellationToken);

        // 在此处调用企业自己的私有解析规则。
        return JsonSerializer.SerializeToElement(new
        {
            summary = $"读取 {rows.Rows.Count} 条元数据",
            pseudoCode = "PAGE ...",
            diagram = "<svg>...</svg>"
        }, new JsonSerializerOptions(JsonSerializerDefaults.Web));
    }
}
```

建议扩展返回 camelCase JSON，便于前端和 MCP 客户端直接使用。每个模块最多注册 50 个工具，操作名只能包含小写字母、数字和下划线。

## 4. 公开的进程内接口清单

命名空间：`AiDataGateway.Extensions`；契约版本：`GatewayExtensionContract.Version == 1`。

| 接口/类型 | 用途 |
| --- | --- |
| `IGatewayExtension` | 扩展入口，提供 `Definition` 并实现 `InvokeAsync` |
| `GatewayExtensionDefinition` | 模块 ID、名称、版本、说明、前端入口和工具清单 |
| `GatewayExtensionToolDefinition` | 工具操作名、说明、JSON Schema、能力声明、UI 可见性和只读提示 |
| `IGatewayExtensionContext` | 当前调用上下文；包含调用者 `Actor`、`Database`、`Logs`、`Monitoring` |
| `IGatewayExtensionDatabase.ListProjectsAsync` | 列出启用项目及其已关联数据源；不返回连接串或密码 |
| `IGatewayExtensionDatabase.QueryAsync` | 按 `projectCode + dataSourceKey` 执行受网关策略保护的只读 SQL |
| `IGatewayExtensionLogs.QueryAsync` | 按项目读取本地 NLog、Seq 或远程 Agent 日志；单次最多 500 条 |
| `IGatewayExtensionMonitoring.ListTargetsAsync` | 列出启用的本机/远端监控节点 |
| `IGatewayExtensionMonitoring.QueryAsync` | 按节点和时间范围读取降采样指标，最多返回指定数量的趋势点 |
| `GatewayExtensionQueryResult` | 查询列、行和是否被行数上限截断 |
| `GatewayExtensionLogResult` | 日志源信息、总数、部分结果标记、警告及结构化事件 |
| `GatewayExtensionMetricResult` | 节点、时间范围、原始点数和指标字典 |

工具必须声明自己需要的能力。多个能力可用按位或组合，例如 `QueryExecute | MetricsRead`。网关只向同时拥有所有所需角色或 OAuth2 Scope 的调用者展示并开放该工具。

| 能力 | 对应 OAuth2 Scope | 可使用的上下文服务 |
| --- | --- | --- |
| `None` | 只要求已登录/已认证 | 不含受保护数据的纯计算工具 |
| `DataSourceRead` | `gateway.datasource.read` | `Database.ListProjectsAsync` |
| `QueryExecute` | `gateway.query.execute` | 项目列表及 `Database.QueryAsync` |
| `LogRead` | `gateway.logs.read` | `Logs.QueryAsync` |
| `MetricsRead` | `gateway.metrics.read` | `Monitoring.*` |

`GatewayExtensionToolDefinition.ReadOnly` 是提供给 MCP 客户端的行为提示，不是沙箱。真正的数据访问边界由上述上下文服务和网关权限共同执行。

## 5. MCP 注册规则

启用并成功加载后，扩展工具会自动出现在下一次 MCP `tools/list` 结果中，不需要修改主程序。公开名称按以下规则生成：

```text
custom_{模块 ID 中的点和横线替换为下划线}_{操作名}
```

例如：

```text
company-metadata + analyze
→ custom_company_metadata_analyze
```

工具说明会自动加上模块名称，输入参数 Schema 来自 `GatewayExtensionToolDefinition.InputSchema`。MCP 客户端已经建立连接时，应重新调用 `tools/list`；当前无状态 Streamable HTTP 实现不主动推送列表变更通知。

## 6. 前端页面

`FrontendEntry` 可指向普通 HTML，也可以指向 Vue/Vite 的 `dist/index.html`。安装后页面会在右侧工作区以独立页签和 iframe 打开，地址形式为：

```text
/custom-modules/{module-id}/ui/
```

页面调用自己的后端操作：

```js
const result = await fetch(
  '/api/custom-modules/company-metadata/invoke/analyze',
  {
    method: 'POST',
    headers: { 'Content-Type': 'application/json' },
    body: JSON.stringify({ projectCode: 'erp', dataSourceKey: 'erp-prod' })
  }
).then(response => response.json())
```

该接口使用当前管理端登录会话，并再次检查工具能力和 `VisibleInUi`。页面可以把返回的代码、Markdown、Mermaid 文本或 SVG 渲染出来；建议优先返回结构化数据，由前端决定展示方式。为了离线和内容安全策略兼容，CSS、JavaScript、字体及图片应放入扩展包，不要依赖公网 CDN。

## 7. HTTP 管理接口

这些接口主要供内置管理页面使用；扩展业务逻辑应优先使用进程内上下文，避免绕过网关约束。

| 方法 | 地址 | 权限 | 说明 |
| --- | --- | --- | --- |
| `GET` | `/api/custom-modules` | 已认证 | 列出当前用户可见模块、页面和工具 |
| `POST` | `/api/admin/custom-modules/install` | Administrator | multipart 字段 `package` 上传 ZIP；同 ID 表示升级 |
| `PUT` | `/api/admin/custom-modules/{id}/enabled` | Administrator | 请求体 `{ "enabled": true }` |
| `DELETE` | `/api/admin/custom-modules/{id}` | Administrator | 删除注册和安装制品 |
| `POST` | `/api/custom-modules/{id}/invoke/{operation}` | 已认证 + 工具能力 | 页面调用扩展操作 |
| `GET` | `/custom-modules/{id}/ui/{path}` | 已认证 + 模块能力 | 读取扩展静态页面 |

安装、启停、删除和每次扩展调用都会写入网关审计日志。

## 8. 示例：本机监控分析报告

仓库中的 `samples/LocalMonitorReportExtension` 是可安装的小型示例。它：

- 通过 `context.Monitoring` 读取本机或远端节点指标；
- 注册 `custom_local_monitor_report_list_targets` 和 `custom_local_monitor_report_generate_report`；
- 在管理页生成健康评分、CPU/内存/磁盘摘要、折线图、分析结论和可交给 AI 的 Markdown；
- 不直接引用基础设施项目，不读取网关数据库文件，也不接触任何凭据。

生成安装包：

```powershell
.\scripts\package-local-monitor-report-extension.ps1
```

输出为 `artifacts/extensions/local-monitor-report-1.0.0.zip`。登录管理员账号后，在“定制化模块 → 模块中心”安装即可。

## 9. 版本与私有交付建议

- 模块 ID 保持稳定，使用语义化版本号；上传相同 ID 的新包即升级。
- 把私有源代码、测试和发布流水线放在企业自己的私有仓库，仅向用户交付 ZIP。
- 在独立测试环境验证 SQL、JSON Schema、不同角色权限和页面兼容性后再安装到正式网关。
- 私有规则如果需要配置，应放在扩展包内部或企业自己的加密配置中；不要把密码写入前端制品。
- 契约大版本不匹配时网关会拒绝加载，并在模块中心显示错误。
