# 服务器监控使用说明

## 1. 功能概览

服务器监控分为两种采集方式：

- 本机：网关启动后自动创建“本机网关服务器”，每 10 秒采集一次，无需配置。
- 远端：在目标服务器运行 `AiDataGateway.MonitorAgent`，使用该节点独立的上报密钥发送指标。

指标存入网关内置 `gateway.db`，页面通过 SSE 收到数据变更后刷新，不轮询服务器。每个节点可以单独选择采集项；CPU、内存、磁盘使用率和系统运行时间属于基础心跳指标，用于在线判断和兼容旧 Agent，不能取消。

目前内置 25 项指标：

- 处理器：整机 CPU 使用率；
- 内存：使用率、已用、可用、页面文件/Swap 使用率和已用容量；
- 存储：磁盘使用率、已用容量、可用容量；
- 网络：累计接收/发送、实时接收/发送速率；
- 网关/Agent 进程：CPU、工作集、专用内存、线程数、句柄数、进程运行时间；
- 系统：运行时间、进程数、逻辑处理器数、活动 TCP 连接数；
- .NET 运行时：托管内存和 GC 堆大小。

指标采用“固定核心列 + 扩展 JSON”的方式保存，后续增加可选指标不需要为每项新增数据库列。

## 2. 查看本机指标

1. 启动 AiDataGateway 并登录。
2. 打开“服务器监控”。
3. 左侧选择“本机网关服务器”。
4. 查看当前 CPU、内存、磁盘、扩展指标、趋势图和历史采样表。

第一次采样的 CPU 可能显示 `0%`，第二次开始会根据两次系统计数差值计算。

### 2.1 配置采集指标

点击节点右上角“配置”，在“采集指标”中按分类勾选。基础心跳指标不可取消；点击“恢复推荐”可回到默认组合。保存后：

- 本机节点从下一次 10 秒采样开始生效；
- 新版远端 Agent 最迟约 5 分钟同步一次配置；
- 旧版 Agent 仍可继续上报基础指标，但不会识别新增的可选指标；
- 未勾选的扩展指标不会写入新采样，历史数据不会被删除。

### 2.2 近期趋势与历史趋势

- “近期趋势”显示最近 120 个采样点，并随 SSE 实时刷新；
- “历史趋势”可选择开始和结束时间，再选择任意已启用指标绘制；
- 单次历史查询最长 31 天；
- 后台在完整时间范围内筛选原始记录，再等距压缩为最多 500 个绘图点；页面同时显示原始记录数和实际趋势点数；
- 不同单位的指标采用各自的纵轴范围，因此一次选择一个指标，避免百分比、字节数和计数混在同一坐标轴上；
- Y 轴刻度会按百分比、容量、速率、时长或计数自动格式化，X 轴会根据实际数据跨度显示时间或日期；
- “近期趋势”的小圆点对应实际采样记录，鼠标悬浮可查看指标名称、精确格式化数值和完整采集时间；圆点带有扩大的透明命中区域，便于选择但不会遮挡折线。
- “历史趋势”不显示采样圆点和悬浮详情，使用标有精确数值的虚线展示当前时间范围内的最高值与最低值，更适合观察整体走势。
- 图表使用固定比例等比缩放，圆点和文字不会随窗口比例变形；Y 轴根据当前指标的数据范围自动缩放，避免小幅波动全部挤在图表底部。
- “近期趋势”和“历史趋势”均按趋势点顺序均匀铺开，即使存在长时间停机空档，数据也不会挤在图表一侧；X 轴标签仍显示每个代表点的实际采集时间。

## 3. 接入远端服务器

### 3.1 在网关创建节点

1. 进入“服务器监控”，点击“新增远端节点”。
2. 填写唯一节点标识和显示名称，可关联一个或多个项目，并选择需要采集的指标。
3. 保存后立即复制节点标识、上报密钥和启动命令。

上报密钥只显示一次。网关只保存 SHA-256 摘要，无法找回原文；遗失时点击“重置密钥”，旧密钥会立即失效。

### 3.2 启动远端 Agent

把发布目录中的 `AiDataGateway.MonitorAgent.exe` 复制到远端服务器，然后运行：

```powershell
AiDataGateway.MonitorAgent.exe `
  --gateway http://网关IP:5127 `
  --target order-prod-01 `
  --secret "创建节点时显示的上报密钥" `
  --interval 10
```

也可以使用环境变量，避免把密钥写入脚本参数：

```powershell
$env:GATEWAY_URL = "http://网关IP:5127"
$env:MONITOR_TARGET = "order-prod-01"
$env:MONITOR_SECRET = "上报密钥"
$env:MONITOR_INTERVAL_SECONDS = "10"
AiDataGateway.MonitorAgent.exe
```

发布产物同时提供单独的 `AiDataGateway-MonitorAgent-*-win-x64.zip`，无需复制完整网关。若还要追溯这台服务器的本地 NLog 文件，请追加 `--log-path`、可选的 `--nlog-config` 和 `--listen http://0.0.0.0:5188`；详细步骤见 [项目与日志接入说明](./项目与日志接入说明.md)。未配置日志路径时 Agent 只上报指标，不开放日志查询服务。

采样间隔允许 5–300 秒。远端服务器必须能访问网关监听地址。网关默认只绑定 `127.0.0.1`；需要远端上报时，在运行网关的 Windows 电脑上设置环境变量并重启软件：

```powershell
[Environment]::SetEnvironmentVariable("AI_GATEWAY_LISTEN_ADDRESS", "0.0.0.0", "User")
```

随后把启动命令中的网关地址写成这台电脑的局域网 IP，并只在 Windows 防火墙中允许可信内网访问 5127 端口。跨主机使用时建议在反向代理后启用 HTTPS。恢复仅本机访问时，把变量改回 `127.0.0.1` 或删除该用户环境变量后重启。

新版 Agent 会使用同一节点密钥读取该节点的指标选择配置，配置接口不返回其他节点、项目或历史数据。

## 4. 数据保留与清理

服务器指标使用“系统设置”中的统一记录保留天数，默认保留 3 天：

- 软件每次启动后会在后台清理一次；
- 软件持续运行时会在每日计划时间清理；
- “立即清理”也会删除超过保留期限的指标记录；
- 删除远端节点会级联删除该节点的历史指标，本机内置节点不能删除。

## 5. AI 读取指标

新建 OAuth2 客户端默认包含：

```text
gateway.metrics.read
```

REST：

```http
GET /api/gateway/projects/order-center/metrics?targetKey=order-prod-01&count=100
Authorization: Bearer <ACCESS_TOKEN>
```

MCP 工具：

```json
{
  "name": "query_server_metrics",
  "arguments": {
    "projectCode": "order-center",
    "targetKey": "order-prod-01",
    "count": 100
  }
}
```

AI 只能读取与项目关联的已启用节点，不能创建节点、重置密钥或上报伪造指标。

## 6. 安全说明

- 每个远端节点使用独立密钥，一个节点泄露不影响其他节点。
- 上报接口仅接受指标写入，不返回节点、项目或历史数据。
- 上报时间仅允许在当前时间前 1 天至后 5 分钟内，避免异常时间污染趋势。
- CPU、内存和磁盘值在服务端再次校验。
- 扩展指标限制为内置白名单，单次上报最多 100 项，且必须是非负有限数值。
- 不要把上报密钥、OAuth2 Client Secret 或 Seq API Key 放入 AI Prompt。
