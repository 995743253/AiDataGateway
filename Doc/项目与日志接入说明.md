# 项目与日志接入说明

## 1. 功能关系

项目用于把同一套业务功能涉及的数据库和日志聚合起来。每个项目拥有唯一的“项目编号”，AI 通过项目编号可以取得：

- 关联的数据源 ID、数据源标识；
- 关联的日志源 ID、日志源标识；
- 日志源类型（本地 NLog、Seq 或远程 Agent）。
- 关联的本机或远端服务器监控节点。

项目与数据源、日志源、监控节点都是多对多关系：一个项目可以关联多个资源，同一个数据库、日志源或服务器也可以被多个项目复用。

## 2. 推荐配置顺序

1. 在“数据源”页面创建并测试数据库连接。
2. 在“日志源”页面创建本地 NLog、Seq 或远程 Agent 日志源；“测试”仅用于提前检查配置，不是查询日志的前置步骤。
3. 在“项目”页面填写唯一项目编号，并选择关联的数据源、日志源和监控节点。
4. 在“应用日志”页面选择日志源并查询。
5. 把项目编号告知 AI；不要把本地路径、Seq API Key 或 OAuth2 Client Secret 发给 AI。

项目和日志源任意一侧都可以维护关联关系。保存项目时，以项目表单中选择的日志源为准；保存日志源时，以日志源表单中选择的项目为准。

## 3. 本地 NLog 日志源

### 3.1 配置方式

可以使用以下任意方式：

- 在“日志文件夹”中直接填写目录，例如 `D:\Logs\OrderApi`；系统默认读取该目录顶层最近修改的 `*.log` 文件；
- 在“日志文件”中填写日志文件绝对路径或通配符，例如 `D:\Logs\order-*.log`；
- 在“NLog 配置”中粘贴完整 XML；
- 在“NLog 配置”中填写 `nlog.config` 的绝对路径；
- 同时填写配置和“日志文件/Layout 覆盖”，用页面值覆盖 XML 中的 `fileName` 或 `layout`。

配置示例：

```xml
<nlog xmlns="http://www.nlog-project.org/schemas/NLog.xsd"
      xmlns:xsi="http://www.w3.org/2001/XMLSchema-instance">
  <targets>
    <target name="applicationFile"
            xsi:type="File"
            fileName="${basedir}/logs/application-${shortdate}.log"
            layout="${longdate}|${level}|${logger}|${message}|${exception}" />
  </targets>
</nlog>
```

若配置包含多个 File target，在“目标名称”中填写要读取的 target `name`。

当前支持解析 `${basedir}`、`${currentdir}`、`${shortdate}`，也会递归展开 `<variable>` 定义的 `${Layout}`、`${LogTxtLocation}` 等变量；其他文件名动态变量按通配符处理。系统先按所选日期筛选文件，再在最多 100 个候选文件中读取不超过 10 MB（包含正好 10 MB）的内容，达到限制时页面会提示。

文件编码会先识别 BOM，再严格检测 UTF-8；中文 Windows 上非 UTF-8 文件会按 GB18030（兼容 GBK/CP936）读取。若 File target 配置了 `encoding`，则优先使用显式编码。

本地 NLog 模式只读取网关所在电脑能够访问的文件系统，不会请求 Seq。若日志位于另一台服务器，推荐使用“远程 Agent”模式；也可使用网关进程有权访问的 UNC 路径或改用 Seq。

### 3.2 容错规则

- 根据下一条记录的时间戳识别上一条记录结束，不要求日志具有额外 end 标记；
- 异常堆栈和消息中的换行会保留在同一条记录中；
- 空字段保留为 `null`，不会挤占相邻字段；
- 支持单行 JSON、格式化的多行 JSON 和 JSON 数组；
- 文件末尾 JSON 未闭合时仍返回原始记录，并标记 `incomplete=true` 和解析提示；
- 应用仍在写入日志时使用共享读取，不会独占或锁定日志文件；
- 文件过大而只读取尾部时，首条残缺记录会明确标记为不完整。
- 只按配置的 Layout 字段解析（时间、级别、线程、来源、消息、异常），不从消息内容里提取键值对，SQL 等消息文本保持原样；
- 配置的 Layout 与实际日志格式不一致时，自动按 `时间|级别[线程][来源] 消息|异常` 的常见 NLog 格式兜底解析，避免级别和字段错乱。

## 4. Seq 日志源

每条 Seq 日志源对应一个 Seq 服务地址和一个 API Key。系统中需要保存多个 Seq 凭据时，创建多条日志源即可；一条日志源不保存多个 Key。

建议在 Seq 中创建仅有 `Read` 权限的 API Key。Key 保存到内置 `gateway.db` 前会通过 ASP.NET Core Data Protection 加密，密钥环再由当前 Windows 用户的 DPAPI 保护。管理页面只显示“是否已配置”，编辑时留空表示不修改。

Seq 地址示例：

```text
http://127.0.0.1:5341
https://seq.example.internal
```

查询使用 Seq 官方 `GET /api/events` 接口，并用 `X-Seq-ApiKey` 请求头认证。页面默认是“小白模式”：直接填写关键词，或填写“属性名 + 属性值”，无需学习表达式。切换到“高级表达式”后才直接输入 Seq Filter，例如：

```text
Application = 'Order.Api' and @Level = 'Error'
```

网关不会写入、删除或修改 Seq 事件。

开始、结束日期会直接合并进 Seq Filter 后再请求 Seq，不会先下载全部日志再在网关内存中过滤。未传日期的 REST/MCP 请求默认查询最近 7 天；页面默认最近 24 小时；单次范围最长 31 天。

Seq 模式只通过 HTTP API 查询，不读取本地日志目录。页面会持续用“本地文件夹采集”和“Seq API 采集”标签标识当前方式。

## 5. 远程 Agent 日志源

将单独发布的 `AiDataGateway.MonitorAgent` 压缩包复制到远程服务器。除指标上报参数外，追加日志目录和监听地址：

```powershell
AiDataGateway.MonitorAgent.exe `
  --gateway http://网关IP:5127 `
  --target order-prod-01 `
  --secret "节点密钥" `
  --log-path "D:\Logs\OrderApi" `
  --nlog-config "D:\OrderApi\NLog.config" `
  --nlog-target File `
  --listen http://0.0.0.0:5188
```

随后在网关“日志源”中选择“远程 Agent”，地址填写 `http://远程服务器IP:5188`，访问密钥填写同一个节点密钥。Agent 在远端按日期读取本地文件并返回结构化结果，日志不会预先全量上传。请只在可信内网放行 5188 端口，并为每台服务器使用不同密钥。

也可以用 `MONITOR_LOG_PATH`、`MONITOR_NLOG_CONFIG`、`MONITOR_NLOG_TARGET`、`MONITOR_LOG_LAYOUT` 和 `MONITOR_LISTEN_URL` 环境变量配置。

## 6. 页面说明

- “项目”：维护项目编号以及数据库、日志源的多对多关联。
- “日志源”：选择“本机 NLog”“Seq API”或“远程 Agent”，维护配置、启停状态并测试连接。
- “应用日志”：按日期统一查看三类结构化事件；选中日志源后点击“查询”会直接读取和解析，不要求先点日志源“测试”。
- “实时日志”：独立页面通过 SSE 接收新增事件，支持关键词、级别和 Seq 属性筛选，页面最多保留最近 500 条。
- “网关审计”：查看谁在何时读取了哪个日志源，以及项目、日志源配置变更。

应用日志查询不会把读取结果复制进 `gateway.db`；审计库只保存查询条件、日志源标识和返回条数，避免业务日志重复堆积。

## 7. 提供给 AI 的信息

推荐只提供：

```text
项目编号：order-center
任务：查询最近的错误日志并结合数据库只读数据分析原因
```

AI 应先调用 MCP `list_projects`，再根据返回的数据库和日志源标识调用 `query_database` 或 `query_logs`。项目关联多个日志源时，调用 `query_logs` 必须填写 `logSourceKey`。

禁止向 AI 提供：

- Seq API Key；
- NLog 配置中的敏感字段；
- OAuth2 Client Secret；
- 管理员账号密码。

## 8. REST API

AI 可用接口：

| 方法 | 地址 | 用途 |
|---|---|---|
| `GET` | `/api/gateway/projects/{projectCode}` | 按项目编号解析数据库、日志源和监控节点标识 |
| `POST` | `/api/gateway/logs/query` | 按项目编号和日志源标识查询结构化日志 |
| `GET` | `/api/gateway/projects/{projectCode}/metrics` | 按项目编号和节点标识查询服务器指标 |

日志查询请求：

```json
{
  "projectCode": "order-center",
  "logSourceKey": "order-api-seq",
  "query": "@Level = 'Error'",
  "searchText": null,
  "propertyName": null,
  "propertyValue": null,
  "level": null,
  "fromUtc": "2026-08-29T00:00:00Z",
  "toUtc": "2026-08-30T00:00:00Z",
  "page": 1,
  "pageSize": 100
}
```

`gateway.logs.read` 是日志专用 Scope。为兼容升级前已经创建的本地 AI 客户端，持有 `gateway.query.execute` 的旧客户端也可以读取日志；新建客户端应申请日志专用 Scope。

小白查询 Seq 时建议把 `query` 设为 `null`，使用 `searchText`、`propertyName` 和 `propertyValue`。`query` 仅保留给高级 Seq Filter。

实时日志使用已登录管理页面的 Cookie 连接 `GET /api/logs/stream`（SSE），不应把管理 Cookie 暴露给 AI。

## 9. MCP 工具

| 工具 | 用途 |
|---|---|
| `list_projects` | 返回项目编号及关联的数据源、日志源、监控节点标识 |
| `list_log_sources` | 列出日志源，可用 `projectCode` 限定项目 |
| `query_logs` | 查询本机 NLog、Seq 或远程 Agent 日志，支持关键词、属性和日期，最多一次返回 500 条 |
| `query_server_metrics` | 查询项目服务器指标，最多一次返回 500 条 |

MCP 不返回日志文件路径、NLog 配置内容或 Seq API Key，也不提供日志源配置修改工具。
